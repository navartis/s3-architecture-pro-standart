# Задание 2. Таблица требований FURPS+

Числа в требованиях - целевые значения из модели нагрузки ниже. Данных о клиентской базе и текущем профиле нагрузки в кейсе нет, поэтому модель собрана на допущениях: они помечены и подлежат уточнению у бизнеса.

## Модель нагрузки

| Параметр | Допущение | Расчет |
| --- | --- | --- |
| Клиентская база | 200 000 клиентов | - |
| Активны в интернет-банке | 20% | 40 000 клиентов |
| DAU интернет-банка | 2% от активных | 800 клиентов в сутки |
| Операций на визит | 10 | 8 000 запросов в сутки |
| Пиковый час | 15% суточного трафика, внутричасовой пик x5 | около 2 RPS |
| Маркетинговая кампания | x20 к обычному пику | 40 RPS |
| Отделения | 500 менеджеров x 40 операций | 20 000 в сутки, пик 1,4 RPS |
| Колл-центр | 200 операторов x 60 запросов | 12 000 в сутки, пик 0,3 RPS |
| Кредитные заявки | 5 000 в месяц | 250 в рабочий день, пик 50 в час |
| Квота БКИ | 10 000 запросов в сутки, 3 RPS | допущение, уточнить по договору |
| Предодобрение | 40 000 онлайн-активных клиентов при TTL 30 дней | около 1 300 вызовов в сутки, 1 RPS |

## Функциональные требования (F)

| Код | Требование | Комментарий |
| --- | --- | --- |
| F1 | Новый клиент видит список доступных депозитов с актуальными ставками на сайте | Депозиты, п. 1 |
| F2 | Подача заявки на депозит с указанием Ф.И.О. и номера телефона на сайте, после чего с клиентом связывается менеджер колл-центра | Депозиты, п. 1 |
| F3 | Клиент видит список доступных депозитов с актуальными и персональными ставками в Интернет-банке | Депозиты, п. 2 |
| F4 | Подача заявки на открытие депозита с указанием счета и суммы в Интернет-банке, подтверждение операции СМС-кодом | Депозиты, п. 2. Определяет место СМС в архитектуре |
| F5 | Подтверждение условий депозита в АБС и обработка заявки по текущему процессу в Бэк-офисе (MVP) | Депозиты, п. 4 |
| F6 | СМС клиенту после подтверждения размера ставки и после открытия депозита | Депозиты, п. 4 |
| F7 | Работа со ставками по депозитам в системе Бэк-офис. Доступ есть у сотрудников и депозитного, и кредитного бэк-офиса | Депозиты, п. 2. Ставки сейчас живут в XLS-файлах, это отдельный блок работы |
| F8 | Оператор консультирует клиента по актуальным ставкам из своей системы в колл-центре банка | Новый кейс, п. 1 (передача ставок в колл-центр) |
| F9 | Получение актуальных ставок файлом, без API-вызовов в партнерском колл-центре | Новый кейс, п. 2. API у партнера невозможен, обмен файлами через SFTP |
| F10 | Новый клиент видит кредитное предложение по ставке, подает заявку на сайте. При наличии паспортных данных сразу получает предварительное решение с суммой и ставкой: одобрение или отказ | Кредиты, п. 1. Предварительное решение, не оферта. Запрос в БКИ только после подтверждения телефона |
| F11 | Продолжение предодобренной заявки с сайта в той же заявке в отделении банка: поиск по телефону и паспорту из АБС. Для полностью нового клиента создается новая заявка | Кредиты, п. 2. Одна заявка на оба канала, без дубля |
| F12 | Клиент видит список кредитов и предодобренное предложение в Интернет-банке, подает заявку с подтверждением СМС-кодом | Кредиты, п. 3 |
| F13 | Повторный скоринг по упрощенной процедуре, если ситуация клиента изменилась | Кредиты, п. 3. Влияет на нагрузку на скоринг |
| F14 | СМС клиенту при изменении статуса кредитной заявки | Кредиты, п. 6 |
| F15 | Проверка доступности ставок и предложений. Ставки и предодобренные предложения показываются каналом до подачи заявки | Добавлено: без этого нельзя выполнить F3 и F12, канал должен читать данные заранее |
| F16 | Статус кредитной заявки доступен клиенту на сайте по ссылке из СМС: номер заявки в СМС, страница статуса по одноразовому токену | Добавлено: обратный путь результата, которого нет в текущем процессе |

## Надёжность (R)

| Код | Требование | Комментарий |
| --- | --- | --- |
| R1 | Каналы доступны 24/7, доступность 99,9% в месяц, это не более 43 минут недоступности. АБС в SLO не входит | Депозиты, п. 6. Объект SLO - каналы, не АБС |
| R2 | RTO 30 минут и RPO 5 минут для БД заявок. Переключение ЦОД проверяется учебным прогоном раз в квартал | Депозиты, п. 6. Проверяемые значения вместо "есть резервный ЦОД" |
| R3 | Заявка не теряется и не дублируется: очередь с состояниями, outbox, парковка и ежедневная сверка. Повторная отправка в течение 30 дней не создает дубль | Добавлено: идемпотентность приема и механизм сохранности, иначе R1 не выполняется по смыслу |
| R4 | При недоступности бюро кредитных историй клиент не получает отказ. Заявка получает решение не позднее одного рабочего дня | Добавлено: отказ по технической причине недопустим, задает деградацию в ADR Task5 |

## Производительность (P)

| Код | Требование | Комментарий |
| --- | --- | --- |
| P1 | Каталог депозитов и ставок p95 200 мс, p99 500 мс. Подача заявки p95 500 мс, p99 1 000 мс. Предварительное решение на сайте p95 3 с, p99 8 с, таймаут ожидания 15 с. Статус заявки p95 300 мс | Депозиты, п. 5. Сейчас справочники грузятся больше секунды |
| P2 | Каналы выдерживают 50 RPS пять минут и 100 RPS одну минуту. Рост RPS в 2 раза не требует изменения конфигурации | Депозиты, п. 6. Проверяется нагрузочным тестом, а не декларацией |
| P3 | Сервис интеграции: не более 8 параллельных вызовов процедур АБС и 600 вызовов в минуту, p95 800 мс, таймаут 2 с, рост CPU базы АБС не более 10% | Депозиты, п. 6. Ключевое ограничение на интеграцию |
| P4 | Предрасчет скоринга: не более 1 300 вызовов в сутки и 1 RPS в окне 01:00-05:00, не более 5% мощности скоринга. Онлайн-запросы приоритетнее | Кредиты, п. 5. Бюджет вместо запрета: перенос на ночь сам по себе нагрузку не убирает |
| P5 | При 10x пике после маркетинговой кампании p95 подачи не хуже 1 с, очередь заявок не более 10 000, отказа нет | Новый кейс, п. 1-2. Ограничитель темпа и очередь |
| P6 | 95% предодобренных заявок получают решение за 4 рабочих часа, 99% в тот же рабочий день | Кредиты, п. 4. Сегодня заявки попадают в конвейер раз в сутки |

## Ограничения (+)

| Код | Требование | Комментарий |
| --- | --- | --- |
| +R1 | Функционал работы с СМС реализуется силами команды банка. Доработка ядра интернет-банка подрядчиком не планируется | Депозиты, п. 2 |
| +R2 | Прямая работа интернет-банка с API или базой АБС в новом процессе не допускается | Депозиты, п. 6 |
| +R3 | Очереди сообщений: на перспективу Kafka. Текущая платформа интернет-банка с Kafka несовместима | Депозиты, п. 3. Определяет момент внедрения брокера |
| +R4 | Суточный обмен между базами АБС и кредитного конвейера ускорить нельзя | Кредиты, п. 4. Обмен обходится стороной, а не ускоряется |
| +R5 | АБС масштабируется только вертикально из-за своей базы данных | Депозиты, п. 6 |
| +R6 | Сотрудники депозитов и сотрудники кредитов не должны иметь доступа к данным друг друга | Процесс открытия депозита, п. 5 (требования безопасности) |
| +R7 | Квота запросов к бюро кредитных историй ограничена договором: 10 000 в сутки и 3 RPS по допущению, значение уточняется | Добавлено: внешняя система с ограничением, влияет на P5 и F10 |
| +R8 | Сырой отчет бюро кредитных историй не хранится без юридического заключения | Добавлено: ограничение на кэширование. Открытый вопрос к банку |
| +R9 | Выдача кредита только после визита в отделение и идентификации клиента. Предварительное решение не оферта и действует 30 дней | Добавлено: осознанное решение против мошенничества, задает границу онлайн-решения |
