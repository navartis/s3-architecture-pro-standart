# Задание 2. Таблица требований FURPS+

| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |

| F4  | Подача заявки на открытие депозита с указанием счёта и суммы в Интернет-банке, подтверждение операции СМС-кодом                                                   | Депозиты, п. 2. Определяет место СМС в архитектуре                                 |
| F5  | Подтверждение условий депозита в АБС и обработка заявки по текущему процессу в Бэк-офисе (MVP)                                                                    | Депозиты, п. 4                                                                     |
| F6  | СМС клиенту после подтверждения размера ставки и после открытия депозита                                                                                          | Депозиты, п. 4                                                                     |

| F8  | Оператор консультирует клиента по актуальным ставкам из своей системы в колл-центре банка                                                                         | Новый кейс, п. 1 (передача ставок в колл-центр)                                    |
| F9  | Получение актуальных ставок файлом, без API-вызовов в партнёрском колл-центре                                                                                     | Новый кейс, п. 2. API у партнёра невозможен, обмен файлами через SFTP              |
| F10 | Новый клиент видит кредитное предложение по ставке, подаёт заявку на сайте. При наличии паспортных данных сразу получает решение по данным бюро кредитных историй | Кредиты, п. 1. Онлайн-запрос в БКИ, ограничения по квоте                           |
| F11 | Продолжение предодобренной заявки с сайта в той же заявке в отделении банка. Для полностью нового клиента создаётся новая заявка.                                 | Кредиты, п. 2                                                                      |
| F12 | Клиент видит список кредитов и предодобренное предложение в Интернет-банке, подаёт заявку с подтверждением СМС-кодом                                              | Кредиты, п. 3                                                                      |
| F13 | Повторный скоринг по упрощённой процедуре, если ситуация клиента изменилась                                                                                       | Кредиты, п. 3. Влияет на нагрузку на скоринг                                       |
| F14 | СМС клиенту при изменении статуса кредитной заявки                                                                                                                | Кредиты, п. 6                                                                      |
| F15 | Проверка доступности ставок и предложений. Ставки и предодобренные предложения показываются каналом до подачи заявки                                              | Добавлено: без этого нельзя выполнить F3 и F12, канал должен читать данные заранее |

## Удобство использования (U)

| Код | Требование                                                                                             | Комментарий                                                   |
| --- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| U1  | Интерфейсы соответствуют принятой в компании дизайн-системе. Привычные цвета и брендированные элементы | Депозиты, п. 5                                                |
| U2  | Единый сценарий подачи заявки в обоих каналах (сайт и интернет-банк) без переучивания клиента          | Добавлено: следствие U1 и единых ставок, влияет на состав API |

## Надёжность (R)

| Код | Требование                                                                                   | Комментарий                                                                       |
| --- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| R1  | Сервисы работают 24/7, доступность 99,9%                                                     | Депозиты, п. 6. Определяет развёртывание в двух ЦОД                               |
| R2  | При сбое ЦОД сервисы интернет-банка остаются доступными, есть резервный ЦОД и переключение   | Депозиты, п. 6.                                                                   |
| R3  | Заявка не теряется при сбое канала или АБС, повторная отправка не создаёт дубль              | Добавлено: идемпотентность приёма, иначе R1 не выполняется по смыслу              |
| R4  | При недоступности бюро кредитных историй клиент не получает отказ - заявка остаётся в работе | Добавлено: отказ по технической причине недопустим, задаёт деградацию в ADR Task5 |

## Производительность (P)

| Код | Требование                                                                                              | Комментарий                                                   |
| --- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| P1  | Отклик по всем операциям в миллисекундах. Справочные данные не должны грузиться секундами               | Депозиты, п. 5. Сейчас справочники грузятся больше секунды    |
| P2  | Горизонтальное масштабирование и равномерное распределение запросов между серверами, приложениями и ЦОД | Депозиты, п. 6.                                               |
| P3  | Онлайн-подача заявок не должна ставить под угрозу работоспособность АБС. База АБС уже перегружена       | Депозиты, п. 6. Ключевое ограничение на интеграцию            |
| P4  | Систему кредитного скоринга не нагружать дополнительными процессами предрасчёта скоринга                | Кредиты, п. 5. Отсюда ночной батч предодобренных предложений  |
| P5  | Наплыв заявок после маркетинговой кампании не выводит из строя колл-центр и внешние интеграции          | Новый кейс, п. 1-2. Ограничитель темпа и очередь              |
| P6  | Предодобренные кредитные заявки обрабатываются в тот же рабочий день                                    | Кредиты, п. 4. Сегодня заявки попадают в конвейер раз в сутки |

| Код | Требование                                                                                                         | Комментарий                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |

| +R2 | Прямая работа интернет-банка с API или базой АБС в новом процессе не допускается                                   | Депозиты, п. 6.                                                                                   |
| +R3 | Очереди сообщений: на перспективу Kafka. Текущая платформа интернет-банка с Kafka несовместима                     | Депозиты, п. 3. Определяет момент внедрения брокера                                               |
| +R4 | Суточный обмен между базами АБС и кредитного конвейера ускорить нельзя                                             | Кредиты, п. 4. Обмен обходится стороной, а не ускоряется                                          |
| +R5 | АБС масштабируется только вертикально из-за своей базы данных                                                      | Депозиты, п. 6                                                                                    |
| +R6 | Сотрудники депозитов и сотрудников кредитов не должны иметь доступа к данным друг друга                            | Процесс открытия депозита, п. 5 (требования безопасности)                                         |
| +R7 | Квота запросов к бюро кредитных историй ограничена договором. Её значение уточняется                               | Добавлено: внешняя система с ограничением, влияет на P5 и F10. Значение - открытый вопрос к банку |
| +R8 | Сырой отчёт бюро кредитных историй не хранится без юридического заключения                                         | Добавлено: ограничение на кэширование. Открытый вопрос к банку                                    |
